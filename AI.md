# AI Usage Disclosure

## 1. Core Logic (Human Authored)
The following files implement the novel contributions of this project. They were manually implemented to ensure strict adherence to the research paper ("Dynamic Context Pruning for Long-Form Dialogue") and to guarantee deterministic behavior in the pruning algorithm.

* **`src/lethus/core/*`**:
    * Includes the DYCP (Kadane's Algorithm) implementation, Semantic Decay logic, and Ghost Graph entity boosting.
* **`src/lethus/api/proxy.py`** (implied):
    * The request interception and stream modification logic required manual handling of the OpenAI protocol.
* **`src/lethus/main.py`**:
    * Service orchestration and startup logic.

## 2. AI-Generated Components
To maximize velocity and focus on the core algorithmic challenge, I utilized AI (Claude Sonnet 4.5, Chatgpt 5.2) to generate the frontend components and infrastructure layer.

* **`frontend/components*` (Next.js Application)**:
    * The UI, including React components, Tailwind styling, was generated by AI to provide a visual interface for the backend proxy without consuming engineering time.
* **`tests/*`**:
    * `test_api_integration.py` and `test_dycp_benchmark.py` were generated to verify the system against edge cases I defined.
* **`docker/*`**:
    * Docker Compose configuration for Milvus and Postgres.
* **`src/lethus/config.py`**:
    * Pydantic settings and environment variable management.

## 3. AI-Assisted Scaffolding (Hybrid)
AI was used to generate the skeleton code, which was then refined by hand.

* **`examples/*`**:
    * The demo scripts (`01_basic_dycp.py`, `07_comparison_demo.py`, etc.) were scaffolded by AI to rapidly create a "showcase" suite, then manually adjusted to correctly call the core library.
* **`src/lethus/storage/*`**:
    * Standard boilerplate for connecting to Milvus and PostgreSQL.
